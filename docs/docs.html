HRL documentation

HRL is a C/C++ rendering library that sits on top of several graphics backends behind one stable API. Version 26.6 · Apache License 2.0

In a hurry? Read Core concepts, then Minimal example. If nothing shows on screen, go to Troubleshooting.

Overview

HRL gives you one set of functions for 2D and 3D rendering, whatever the graphics API underneath. You pick a backend once at start-up and the rest of your code does not change.

  • Explicit. Nothing exists until you create it, and everything you create must be destroyed. No hidden allocations, no garbage collection.
  • Multi-backend. OpenGL 3.3/4.5, Vulkan, Direct3D 11/12, Metal, NVN and GNM share the same functions. Feature coverage differs per backend, see the feature matrix.
  • Complete scene model. Meshes, sprites, skeletal meshes, PBR materials, lights, cameras, viewports, VFX, widgets and debug drawing.
  • Windowing-agnostic. HRL does not open windows or read input. You bring your own layer (GLFW, SDL, Win32…) and hand HRL a function loader.

Getting the code & building

git clone https://github.com/oscar-soirey/Horizon-Rendering-Library.git
cd Horizon-Rendering-Library

The project uses CMake (CMakeLists.txt at the repository root). A typical out-of-source build:

cmake -S . -B build
cmake --build build --config Release

On Windows, helper scripts are included at the root: build.bat, build-hrl-example.bat, generate-cmake-project.bat and generate-bindings.bat.

Choosing a backend

  • OpenGL 3.3 is the most complete backend today: post-processing, shadows, volumetric fog, GI and more run here.
  • Vulkan, Direct3D 12 and Metal are the backends with ray tracing and virtualized geometry.
  • Direct3D 11 covers the core feature set.
  • Check the feature matrix before relying on a feature: the same call can be fully, partly or not yet supported depending on the backend.

The matrix lists OpenGL 3.3, Vulkan, D3D11, D3D12 and Metal. It has no column for OpenGL 4.5, NVN or GNM.

Core concepts

Explicit object model

HRL does not manage object lifetimes for you. Every object (scene, mesh, texture, shader, material, light, camera, viewport, font) must be created before use and destroyed when no longer needed. If you did not call the HRL_Create* function for an object, it does not exist.

  • A mesh without a material will not render correctly.
  • A viewport without a camera will not render.
  • A material without a shader is invalid.
  • A scene with no camera produces no output.

Conventions

Lifecycle

HRL_Init(backend)
HRL_InitContext(width, height, loader)
|
+-- Create scenes, cameras, viewports
+-- Create shaders, materials, textures
+-- Create meshes and assign materials
+-- Create lights
|
+-- Main loop:
|     HRL_BeginFrame()
|     update transforms, uniforms, ...
|     HRL_EndFrame()
|     swap buffers (your windowing layer)
|
HRL_Shutdown()   // cleans every object

HRL_Shutdown cleans every remaining object, so a program that exits right after it does not have to delete things one by one. Delete objects yourself when you want to free GPU memory during the run, for example when leaving a level.

Initialization

HRL_Init(HRL_uint api);

Selects the graphics backend. Must be called first, before any other function.

HRL_InitContext(HRL_uint width, HRL_uint height, void* loader);

Creates the rendering context. loader is your platform's function loader (e.g. glfwGetProcAddress for OpenGL). Create your window and make its context current before calling this.

HRL_Shutdown();

Releases all internal resources. Call it before closing the window.

The frame loop

HRL_BeginFrame();
HRL_EndFrame();

Everything that changes what the frame looks like happens between these two calls: moving meshes, lights and cameras, setting material uniforms, issuing HRL_Draw* debug calls. Presenting the image is up to your windowing layer, so call your swap function (e.g. glfwSwapBuffers) after HRL_EndFrame.

Only immediate-mode debug geometry has to be repeated every frame (see Debug utilities).

Scenes

A scene is the top-level container for renderable objects, lights and cameras. You need at least one to render anything.

HRL_id HRL_CreateScene(int renderOnScreen);

Pass HRL_True to render to the screen, or HRL_False to render into an off-screen texture (480×480 by default; use HRL_ResizeSceneTexture to change it). An off-screen scene is the basis for render-to-texture and for post-processing pipelines.

void HRL_DeleteScene(HRL_id sceneid);

Several scenes can coexist, for example a 3D world scene and a separate 2D interface scene.

Meshes & sprites

HRL_id HRL_CreateMesh(HRL_id sceneid, HRL_uint type, float* vertices);
HRL_id HRL_CreateMeshFromFile(HRL_id sceneid, HRL_uint type, const char* data, size_t size);
HRL_id HRL_CreateMeshSprite(HRL_id sceneid);
typeUse for
HRL_2D_MeshFlat geometry in 2D scenes.
HRL_3D_MeshStatic 3D geometry.
HRL_3D_SkeletalMeshAnimated, skinned 3D geometry.

File loading supports .fbx and .obj. As with textures, data is the raw file content read in binary mode and size its length in bytes. A sprite is a textured quad for 2D and UI work; see the built-in HRL_SpriteShader below.

A mesh needs a material before it renders:

void HRL_SetMeshMaterial(HRL_id meshid, HRL_id matid);

Transforms

void HRL_SetMeshLocation(HRL_id meshid, float x, float y, float z);
void HRL_SetMeshRotation(HRL_id meshid, float pitch, float yaw, float roll);
void HRL_SetMeshScale(HRL_id meshid, float x, float y, float z);

Rotation is given as pitch, yaw and roll, as for lights and cameras.

Level of detail (LOD), indexed meshes and screen-space displacement maps are supported on every backend in the matrix.

Materials & shaders

A shader is a compiled GPU program. A material is an instance of a shader with its own uniform values; one shader can back many materials.

HRL_id HRL_CreateShader(const char* vertSrc, size_t vertSize, const char* fragSrc, size_t fragSize);
HRL_id HRL_CreateMaterial(HRL_id shaderid);

Shader sources are passed from memory, in the language of the selected backend (GLSL for the OpenGL backends).

Uniforms

void HRL_MaterialSetFloat(HRL_id matid, const char* name, float value);
void HRL_MaterialSetVec3(HRL_id matid, const char* name, float x, float y, float z);
void HRL_MaterialSetTexture(HRL_id matid, const char* name, HRL_id textureid);
// Also available: SetInt, SetBool, SetVec2, SetVec4

name must match the uniform name in your shader. Textures are bound by name too; for the standard PBR slots use the predefined names such as HRL_T_ALBEDO.

PBR materials

The standard material model covers albedo, normal map, metallic, roughness, specular and alpha, with texture filtering. All of it is supported on every backend listed in the matrix.

Textures & fonts

HRL_id HRL_CreateTexture(const char* data, size_t size);

Formats: png, jpeg, bmp, tga, gif (first frame), hdr, psd (partial). data is the raw file content read in binary mode. Do not decode the image yourself first.

HRL_id HRL_CreateTextureFromText(const char* text, HRL_id fontid,
    float fontSize, float wrapWidth,
    float r, float g, float b,
    float bg_r, float bg_g, float bg_b, float bg_a);

Rasterizes a UTF-8 string into a texture. wrapWidth = 0 disables wrapping; bg_a = 0 gives a transparent background. The result is a regular texture: bind it to a material like any other. To change the text, create a new texture and delete the old one.

HRL_id HRL_CreateFont(const char* data, size_t size);

Loads a .ttf font from memory. Required before HRL_CreateTextureFromText.

typeBehaviour

HRL_DirectionalLightParallel rays, like the sun. Direction comes from its rotation.
HRL_SpotLightA cone from a position, along its rotation.
void HRL_SetLightColor(HRL_id lightid, float r, float g, float b);

Cameras & viewports

A camera defines the point of view; a viewport maps a camera's output to a region of the screen. You need both.

HRL_id HRL_CreateCamera(HRL_id sceneid, HRL_uint type);  // HRL_Ortho or HRL_Perspective
void HRL_SetCameraPosition(HRL_id camid, float x, float y, float z);
void HRL_SetCameraRotation(HRL_id camid, float pitch, float yaw, float roll);
void HRL_SetCameraPerspectiveFov(HRL_id camid, float fov);    // degrees
void HRL_SetCameraOrthoVertical(HRL_id camid, float height);  // world units

// Normalized [0..1]. (0,0) = top-left, (1,1) = bottom-right.
HRL_id HRL_CreateViewport(HRL_id sceneid, HRL_id cameraid, float x, float y, float w, float h);

Use HRL_Perspective with HRL_SetCameraPerspectiveFov for 3D, and HRL_Ortho with HRL_SetCameraOrthoVertical for 2D and UI.

Split-screen

Several viewports can share a scene (split-screen, picture-in-picture). Give each its own camera:

HRL_id camA = HRL_CreateCamera(scene, HRL_Perspective);
HRL_id camB = HRL_CreateCamera(scene, HRL_Perspective);

HRL_CreateViewport(scene, camA, 0.0f, 0.0f, 0.5f, 1.0f);  // left half
HRL_CreateViewport(scene, camB, 0.5f, 0.0f, 0.5f, 1.0f);  // right half

2D voxel worlds

HRL has a built-in 2D voxel world. Voxels are squares in the XY plane. A voxel's type is a number, and type == 0 is reserved for empty space. Each type gets a color.

Backend. Voxel rendering is implemented on the OpenGL 3.3 backend.

Functions

FunctionPurpose
HRL_SetVoxelSizeSets the world dimensions in voxels (width and height).
HRL_SetVoxelPhysicalSizeSets the size of one voxel in world units.
HRL_SetVoxelChunkSizeSets the chunk size, in voxels.
HRL_SetVoxelTypeColorSets the RGBA color of a voxel type.
HRL_LoadVoxelWorldCopies a complete world into HRL.
HRL_SetVoxelTypeChanges one voxel.
HRL_GetVoxelTypeReads one voxel.

The calls shown below take the scene first. Check hrl.h for the exact parameter lists of the others. The world is described by an array of HRL_Voxel.

HRL_SetVoxelSize(sceneid, 1024, 1024);
HRL_SetVoxelType(sceneid, x, y, type);

Memory layout

After HRL_SetVoxelSize(scene, 1024, 1024), the array given to HRL_LoadVoxelWorld is indexed row by row:

voxels[y * 1024 + x]

How it works

  • Storage stays on the CPU. HRL_LoadVoxelWorld copies the whole world into RAM but does not upload it all to the GPU.
  • Chunk streaming. The world is cut into chunks. HRL intersects each camera's frustum with the XY plane and keeps GPU buffers only for the chunks that are visible, plus a margin of one chunk. Chunks that leave this zone are destroyed.
  • Greedy meshing. Inside a chunk, neighbouring voxels of the same type are merged into rectangles. A uniformly filled chunk is one rectangle instead of one quad per voxel; a checkerboard is the worst case with one rectangle per voxel.
  • Live edits. HRL_SetVoxelType updates the CPU data at once and marks the chunk as dirty. The chunk is regenerated at the next render, and its GPU buffer is replaced if it is loaded.
  • Colors. The color is baked into the vertices of each chunk, so HRL_SetVoxelTypeColor forces every loaded chunk to be rebuilt. Set colors before loading the world, not every frame.

Voxels use fog and the existing G-buffer outputs, so they combine with the rest of the pipeline. The voxel change introduced the structure HRL_Voxel and moved the API version from 0.6 to 0.7.

Sketch

// World of 96 x 64 voxels, three types, drawn with chunks of 16 x 16
HRL_SetVoxelSize(scene, 96, 64);
HRL_SetVoxelChunkSize(scene, /* 16, 16 */);
HRL_SetVoxelTypeColor(scene, /* type 1, 2, 3 and their RGBA colors */);
HRL_LoadVoxelWorld(scene, /* your HRL_Voxel array, y * 96 + x */);

// Later, in the frame loop: dig a voxel
HRL_SetVoxelType(scene, 48, 48, 0);   // 0 = empty

A complete version of this scene, with a voxel modified when SPACE is pressed, is in the repository's example folder.

Post-processing

A post-process is created with HRL_CreatePostProcess. It depends on a scene and a material, so build the material from your own shader first (see hrl.h for the exact parameters). Post-process materials are supported on OpenGL 3.3 only for now.

Related screen-space effects (ambient occlusion, god rays) and environment features (sky sphere, environment mapping) are listed in the matrix.

Error handling

HRL records the last error. Query it after any call that may fail:

HRL_Error HRL_GetLastError(const char** detail, HRL_Severity* severity);

Or register a callback invoked on every error:

void HRL_RegisterErrorCallback(HRL_ErrorCallback callback);
// void callback(HRL_Error code, HRL_Severity severity, const char* detail)

The macro HRL_CheckErrors() prints any pending error with file and line (handy in debug builds).

SeverityMeaning
HRL_SEVERITY_WEAK_WARNINGProbably harmless; worth a look.
HRL_SEVERITY_WARNINGSomething is wrong, rendering continues.
HRL_SEVERITY_ERRORAn operation failed.
HRL_SEVERITY_FATALHRL cannot continue.

Recommended setup

void on_error(HRL_Error code, HRL_Severity severity, const char* detail) {
    fprintf(stderr, "[HRL %d] %s\n", (int)severity, detail ? detail : "(no detail)");
}

HRL_RegisterErrorCallback(on_error);   // register early, right after HRL_Init

HRL_id mesh = HRL_CreateMeshFromFile(scene, HRL_3D_Mesh, data, size);
if (mesh == HRL_INVALID_ID) {
    // creation failed: the callback has already reported why
}

Because a missing object and an invalid object both produce silent black output, a callback registered from the start is the fastest way to find a mistake.

Minimal example

// 1. Initialize
HRL_Init(HRL_OpenGL45);
HRL_InitContext(1280, 720, glfwGetProcAddress);

// 2. Scene, camera, viewport
HRL_id scene    = HRL_CreateScene(HRL_True);
HRL_id camera   = HRL_CreateCamera(scene, HRL_Perspective);
HRL_id viewport = HRL_CreateViewport(scene, camera, 0.f, 0.f, 1.f, 1.f);
HRL_SetCameraPerspectiveFov(camera, 60.f);
HRL_SetCameraPosition(camera, 0.f, 0.f, -5.f);

// 3. Shader, material, texture
HRL_id shader   = HRL_CreateShader(vert_src, vert_len, frag_src, frag_len);
HRL_id material = HRL_CreateMaterial(shader);
HRL_id texture  = HRL_CreateTexture(png_data, png_size);
HRL_MaterialSetTexture(material, HRL_T_ALBEDO, texture);

// 4. Mesh
HRL_id mesh = HRL_CreateMeshFromFile(scene, HRL_3D_Mesh, obj_data, obj_size);
HRL_SetMeshMaterial(mesh, material);

// 5. Render loop
while (!glfwWindowShouldClose(window)) {
    HRL_BeginFrame();
    HRL_EndFrame();
    glfwSwapBuffers(window);
    glfwPollEvents();
}

// 6. Cleanup
HRL_Shutdown();

What each step does

  1. Initialize. Choose the backend, then create the context with your loader.
  2. Scene, camera, viewport. The scene holds everything, the camera looks at it, the viewport puts the result on screen.
  3. Shader, material, texture. The material is the shader plus its values, here an albedo texture.
  4. Mesh. Load geometry from memory and give it its material.
  5. Loop. Draw a frame, then present it with your windowing layer.
  6. Cleanup. HRL_Shutdown releases everything.

The camera sits at z = -5, so a mesh near the origin should be in view. Add a light with HRL_CreateLight if your shader is lit.

Troubleshooting

HRL does not guess for you, so a black window almost always means a missing object. Go through the list in order.

SymptomCheck
Black window, nothing at allIs there a camera in the scene? Is there a viewport that uses it, covering 0,0,1,1? Are you calling HRL_BeginFrame and HRL_EndFrame every iteration?
Mesh missingDid you call HRL_SetMeshMaterial? Does the material have a valid shader? Is the mesh in front of the camera and inside its view (for a 60° camera at z = -5, near the origin)?
Mesh is black or flatIs the shader lit? Create at least one light. Check that the albedo texture was bound with HRL_MaterialSetTexture.
A HRL_Create* returns HRL_INVALID_IDRead the error: HRL_GetLastError or your callback. Check that its dependencies (scene, material…) were created first.
Texture fails to loadOpen the file in binary mode and pass the raw bytes and their exact size. Check that the format is supported.
Text does not appearDid you create a font with HRL_CreateFont? Is the background alpha 0 and the text color different from the background?
Crash in HRL_InitContextCreate the window and make its context current first. Pass the correct loader for the backend.
Effect has no resultLook at the feature matrix: the effect may not be implemented on your backend.
Debug shapes flicker or vanishImmediate-mode HRL_DrawDebug* calls must be repeated every frame.
Voxel world not visibleVoxel rendering is on OpenGL 3.3. Check the world size, that types are not all 0, that colors are set and that the camera looks at the XY plane.

FAQ

Does HRL create the window?

No. HRL only renders. Use GLFW, SDL, Win32 or any other layer and pass HRL the right loader.

Do I have to delete everything myself?

For objects you want to free before the program ends, yes. HRL_Shutdown cleans every remaining object.

Can I switch backend at run time?

The backend is chosen with HRL_Init, which must be the first call. Pick it at start-up, for example from a command-line option.

Can several materials share a shader?

Yes, that is the intended use. One shader is compiled once; each material holds its own values.

Can I render into a texture?

Yes. Create the scene with HRL_False; it renders into an off-screen texture (480×480 by default, resizable with HRL_ResizeSceneTexture).

Which backend should I use?

For maximum features today, OpenGL 3.3. For ray tracing or virtualized geometry, Vulkan, Direct3D 12 or Metal. See Choosing a backend.

Can I use HRL from another language?

The library has a C API and ships a bindings folder in the repository. See it for the languages available.
